# Архитектура FlexoColor Lab

Статическое React/TypeScript приложение. Сервер не требуется. Hash-навигация работает на GitHub Pages без rewrite. Все бизнес-данные и обработанные фото находятся в IndexedDB текущего origin. Service worker кэширует только ресурсы сборки; пользовательские изображения в precache не попадают. Другой адрес или браузер означают отдельную базу.

## Модули

| Папка              | Ответственность                                                     |
| ------------------ | ------------------------------------------------------------------- |
| `src/ui`           | Сценарии сравнения, карточки, формы, управление фото                |
| `src/domain`       | Zod-схемы данных, decimal.js, массы и составы                       |
| `src/color`        | sRGB transfer, XYZ, Bradford D65 → D50, CIELAB, ΔE76, CIEDE2000     |
| `src/images`       | Декодирование, sRGB Canvas, ROI, фильтры и статистика               |
| `src/storage`      | Dexie, миграции, транзакции, резервные копии, журнал и эксперименты |
| `src/measurements` | CSV Lab/спектры                                                     |
| `src/correction`   | Независимый ColorCorrectionEngine и интерфейс MixingModel           |

## Заказ, Pantone и простой цикл

Order содержит несколько OrderColor. У каждого цвета стабильный ID, название/номер Pantone, версии эталона и свой текущий эталон. Переключение между Pantone не переносит составы, пробы или добавки. Изменение номера сохраняет историю и очищает текущий эталон, чтобы прежний цвет не использовался как новый автоматически.

Batch остаётся внутренней сущностью для истории одной фактической смеси: orderId, colorId, referenceId. Оператору не требуется создавать запуск, вводить дату или смену — текущая смесь создаётся при первом сохранении/добавке. Изменение фактического состава после проб создаёт новую смесь с сохранением прежней. Старые runDate/shift сохраняются при миграциях.

Исходный состав может быть неизвестен: compositionKnown=false, initial=[]. Тогда UI не показывает выдуманную общую массу и проценты смеси; суммы и доли известных добавок не выдаются за весь состав. Такие эксперименты исключаются из обучения.

Несколько добавок сохраняются одной транзакцией. Каждая имеет собственное событие и общий operationId. Ошибка одного компонента отменяет всю операцию. Вклад отдельных красок при совместной добавке не определяется.

Модуль progress независимо рассчитывает текущий цвет относительно эталона и предыдущей пробы. «Ближе / дальше» выводится только при совместимых условиях и одинаковом ID целевого измерения. Изменение меньше 0,01 относится к точности отображения, а не к производственному допуску. Советы описывают направление и наблюдаемый результат без выдуманного выбора краски и дозы.

## Данные

Ink различает производителя, код, тип, группу, партию и заметки; названия не определяют физические свойства. Recipe имеет familyId и версию, компоненты с массами строками, тип и описание источника. Batch хранит исходный состав и неизменяемые события добавок; текущие массы и проценты выводятся из них. Массы ограничены тремя десятичными знаками. Исходная и текущая суммарная масса вычисляются, поэтому не расходятся с компонентами. Будущие параметры материала, анилокса, УФ и скорости выделены в optional production.

Sample хранит целевое и текущее Measurement, снимок состава, ID фотографий, курсор событий добавок и комментарий. История добавок не редактируется и не удаляется через UI. Ошибку операции следует документировать в комментарии; корректировка списания/перемешивания остатков требует отдельной модели расхода в будущей версии.

Measurement различает PHOTO_UNCALIBRATED, PHOTO_CALIBRATED, SPECTRO_LAB и SPECTRO_SPECTRAL. Хранит условия, белую точку, наблюдателя, геометрию и режим, ID профиля/калибровки, Lab, статистику ROI и необязательный спектр. Для фото сохраняются captureId, нормированные прямоугольники и фильтры. Значения Lab для фото рассчитаны из поканальной медианы RGB, а не среднего Lab отдельных пикселей. Среднее RGB и разброс показываются отдельно. Поканальная медиана — робастная сводка, она не обязана совпадать с одним реальным пикселем.

Profile первой версии — только REPEATABILITY_ONLY: независимые снимки одной контрольной области, условия, максимальная попарная ΔE00 и заданный пользователем предел. Он не изменяет RGB и не присваивает PHOTO_CALIBRATED. Повторный анализ того же снимка заменяет контрольную запись, а не увеличивает число независимых снимков.

Experiment создаётся между двумя пробами, если были добавки. Включает составы, измерения до/после, все добавки, условия и исключение из обучения. Изменившиеся условия/источники/профили, некалиброванные фото и неоднородные ROI помечают запись и по умолчанию исключают её. Снятие исключения оператором не валидирует модель. Агрегация разных условий не выполняется. Если между пробами несколько добавок, это один эксперимент с несколькими воздействиями, а не независимый эффект каждой краски.

## Изображения и пределы

Декодирование использует браузерный EXIF и ICC pipeline (`createImageBitmap`, fallback HTMLImageElement). Canvas запрашивается как sRGB; браузер определяет поддержку профиля. Неизвестный или некорректно обработанный профиль остаётся источником неопределённости. JPEG/PNG и другие форматы принимаются только если их декодирует браузер. RAW/HEIC не гарантированы.

Файл ограничен 35 МБ, длинная сторона приводится максимум к 2400 px. Для крупных ROI используется детерминированная равномерная выборка до 150 000 пикселей из объединения ROI, без двойного учёта пересечений. Это уменьшает нагрузку на мобильную память. Число пикселей и доля исключений относятся к проанализированной выборке. В базе хранится обработанное PNG-изображение, исходный файл не сохраняется. Полный исходный кадр следует архивировать отдельно, если он необходим для аудита.

Фильтры прозрачности, тёмных и нейтрально-светлых пикселей, расстояния от медианы — эвристики. Значения настраиваются; насыщенные каналы не считаются автоматически бликом. Фильтрация не исправляет плохое освещение и может исключить полезные пиксели. Разброс RGB — индикатор неоднородности, не доверительный интервал ΔE.

## Точность и расширение

Результат CIEDE2000 вычисляется при kL=kC=kH=1. Порог пригодности по умолчанию отсутствует. Вычисления проверены по 34 дополнительным парам Sharma–Wu–Dalal. Фотооценка не является приборным измерением даже при маленькой разнице. ΔC* обозначает разницу CIELAB chroma, а не физическую концентрацию пигмента.

ColorCorrectionEngine по умолчанию возвращает INSUFFICIENT_CALIBRATION_DATA, пустые добавки, null для прогноза и неопределённости. Подключённая модель должна иметь validated=true и реализовать контракт. Проверка качества модели, независимый набор, область применимости и распространение неопределённости потребуют отдельного этапа разработки. Kubelka–Munk нельзя применять без спектральных данных, проверки оптических предпосылок, подложки и толщины слоя.

## Хранение и восстановление

Схема IndexedDB имеет версии 1–4. Версия 2 добавляет статус и коллекции партии, версия 3 — заказы и связь запусков. Каждый старый замес переносится в отдельный заказ; группировка по Pantone или имени не выполняется. При наличии сохранённой пробы её целевое измерение становится исходным эталоном перенесённого заказа. Исторические пробы сохраняются целиком. Версия 4 добавляет цвета заказа и связь colorId. JSON backup имеет версию 4; копии v2/v3 валидируются и мигрируют перед восстановлением. Перед восстановлением проверяются типы, массы, ID и ссылки; замена выполняется одной транзакцией и требует подтверждения после показа содержимого копии. Старые или неизвестные форматы не принимаются молча. Записей в рабочей базе можно избежать импортом демонстрации в отдельном браузере/профиле; импорт полностью заменяет базу.

Тесты: Vitest для математики, ввода, хранилища и движка; Playwright для мобильных пользовательских сценариев Chromium и WebKit, включая реальный service worker. Это эмуляция viewport, не физическая сертификация Safari iOS. Производственный допуск требует испытаний на фактическом iPhone, материалах и освещении.
